## 新发现及修复

| 优先级 | 问题与影响 | 修复与验证 |
|---|---|---|
| P1 | 部分可选规格没有进入上游请求，可能出现所选收费规格与实际请求不一致 | 覆盖全部 249 条路由的标量参数变更检查；固定规格不再提供虚假的可选档位，不能生效的参数在扣款前拒绝 |
| P1 | InfoToken 图片复用了其他渠道的请求字段，质量未传递，参考图未使用其编辑接口 | 使用 `resolution`、`quality`、`aspect_ratio`，有参考图时走 `/v1/images/edits` 并传 `image_urls` |
| P1 | Midjourney 上游名为 `8.1/8.2` 时被误判为单图模型，四张结果只保存一张 | 根据源模型和上游模型共同识别结果上限，后台／用户模型元数据与任务快照保持一致；模拟四图完整保存 |
| P1 | 带幂等头的可重放 POST 请求在复用连接断开时可能由 HTTP 客户端隐式重发，上游未必实现去重 | 新旧供应商提交均禁用 POST 请求体自动重放；建立连接后模拟接收请求并断开，验证只提交一次 |
| P2 | 已受理任务轮询时遇到网络断线即失败退款，用户可能丢失仍在上游生成的结果 | 将连接中断与永久协议错误区分，在任务超时范围内继续查询原任务，不重新提交生成 |
| P2 | 轮询返回其他任务的失败错误时，在核对任务 ID 前就把当前任务判为失败 | 先筛选任务身份，再解释任务级错误；模拟“断线 → 其他任务失败 → 原任务成功”通过 |
| P2 | MYNEWAPI 的 Gemini 图片调用使用专用认证头，但同源受保护结果下载使用 Bearer，可能生成成功后下载失败 | 提交、轮询和同源下载统一使用该路由认证方式；模拟专用认证头下载通过 |
| P1 | 重复导入可以复用 route_id 改成其他源模型／类型，或者修改地址／协议后仍保持启用，容易把旧价格用于新绑定 | 禁止 route_id 跨供应商／源模型／类型复用；上游模型、地址或协议配置变化后停用对应模型；导入失败整体回滚 |
| P2 | 清单供应商仍能调用旧模型目录的同步、发布和密钥接口，产生脱离独立路由的无效记录 | 服务端拒绝这些旧入口并指向供应商路由管理，避免无凭据同步、错误发布或设置不起作用的密钥 |
| P2 | 提交前检查使用占位提示词，真实提示词的受限标记与模型长度限制只在扣费后才发现 | 提交时用真实提示词再检查一次；Midjourney 规格覆盖标记与 Kinovi 超长提示词在建任务／扣费之前拒绝 |
| P2 | 修改适配器后，数据库中旧参数仍存在；管理员删掉必填音色也可能绕过界面检查 | 增加原生能力校验；新增「更新参数规范」操作，明确确认后更新参数、停用模型、保留原价格，供管理员复核 |

规格修复具体涉及 Afrifex 固定分辨率模型、InfoToken 图片质量、Kinovi Kling 4K 固定档位、RunningHub `auto/medium` 重复档位、Runware Kling Standard 不生效的画面比例。对不接受的选项采用明确拒绝，避免默默改成其他规格。
