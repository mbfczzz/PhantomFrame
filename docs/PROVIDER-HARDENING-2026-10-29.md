# 供应商配置、同步与性能复核（2026-10-29）

本轮继续检查供应商实例架构，使用隔离 MySQL 3307、Redis 6380 和本机模拟上游。未访问生产数据库，真实模型及真实支付调用均为 0。

## 发现与修复

| 问题 | 修复与验证 |
| --- | --- |
| 普通图片／视频协议可以添加或发布不支持的文本模型，上传服务也能添加生成模型 | 添加、发布、模型保存和报价统一使用协议能力校验；页面类型选项同步过滤。视频兼容协议新增时默认选择视频 |
| 粘贴的 Key 首尾空白未清理，明显无效的专用协议 Key 可以保存 | 保存前去除首尾空白，拒绝内部空白、控制字符及无效占位 Key；独立模型 Key 使用同样校验。无效更新不覆盖原密钥 |
| 同一供应商重复点击拉取会并发请求上游 | 按实例设置带所有者标识的 Redis 同步锁，重复请求返回 409。不同实例仍可并行；成功、取消、响应读取超时与数据库失败均释放锁 |
| 拉取请求取消后，目录事务仍可能继续等待数据库锁 | 网络读取与目录事务共用 20 秒上下文；超时返回 504，未提交的批次完整回滚。300ms 超时的行锁等待测试验证先前写入也被回滚 |
| 目录类型存在大小写或首尾空白时可能丢失参数；被拒绝的 3D 条目可能抢占相同 ID | 先规范化类型，接受条目后再标记去重。`3D` 后紧跟同 ID 的有效文本模型可以正常保留；未知类型保留供人工确认 |
| 每次启动都为已有目录逐个执行无效补齐写入 | 只查询缺失的供应商／模型组合。完整的 22 个演示模型目录由 23 次 SQL 降为 1 次查询，缺失条目可补齐且已审核名称、参数、密钥不受影响 |

类型校验、Key 保存、重复拉取和启动补齐四组回归已记录修复前的失败，再验证修复后通过。正文读取超时、类型规范化、跨实例并行和事务取消另有新增回归覆盖。

`TxContext` 只用于可取消的目录同步事务；余额和订单仍沿用原有事务完成逻辑。一次性旧目录清理的迁移版本保持 `provider-instances-reset-v1-20261028`，不会因为本轮修复再次清空已升级的数据。

## 接口耗时复测

所有功能回归结束后单独运行与上一轮相同的本地诊断：20 个供应商、1000 个模型、2000 条价格；目录模拟响应固定等待 50ms。以下是本轮单次诊断的样本分位数，不能当作生产 SLA。

| 场景 | P50（ms） | P95（ms） |
| --- | ---: | ---: |
| 供应商列表 | 4.9 | 5.7 |
| 渠道目录每页 20 条 | 5.1 | 5.8 |
| 后台模型列表 1000 个 | 91.5 | 110.1 |
| 用户模型列表 1000 个 | 94.5 | 143.1 |
| 报价 | 3.3 | 3.6 |
| 提交任务返回入队结果 | 14.2 | 23.1 |
| 模型列表 4 并发 | 140.7 | 178.3 |
| 同账号入队 4 并发／混合撤销 | 39.6 | 49.0 |
| 重复同步 1000 条目录 | 105.3 | 125.4 |

首次同步新增 950 条耗时 177.6ms，仅测一次。模型列表仍为 4 次 SQL，目录页仍为 5 次 SQL。新增同步锁与取消处理后，本次样本未见明显性能退化；相较上一轮的小幅变化不能归因于稳定提速。

另外 6 个模拟文本任务在 2 个工作槽运行，每个上游请求固定等待 100ms，最后完成时间约 358ms；仅发生 6 次模拟生成调用，扣款与任务数一致。上述入队探针随后立即撤销并验证退款，不代表真实模型的生成时长。本轮未提高任务并发数。
