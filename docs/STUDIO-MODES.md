# 创作输入区与模式

参考素材、提示词和创作参数整合为一个输入面板：素材在上方，模式／模型／比例／时长／分辨率／线路位于提示词下方，报价与生成操作位于面板底部。其他参数在「更多设置」中展开。手机上控件换行，生成按钮随面板滚动。

| 类型 | 模式 | 素材行为 |
| --- | --- | --- |
| 图片 | 文生图 | 不携带参考素材 |
| 图片 | 图生图 | 至少一张图片，数量仍受模型配置限制 |
| 视频 | 文生视频 | 不携带参考素材 |
| 视频 | 图生视频 | 使用图片；支持首尾帧协议时显示首帧／尾帧槽位 |
| 视频 | 全能参考 | 按模型能力提供图片、视频、音频入口，至少添加一种参考素材 |

模式不改变模型售价，也不会创建新的上游能力。不支持的模式置灰。切换模式会移除不兼容素材及对应提示词引用，再重新获取报价；类型／分辨率／合计数量限制继续由当前模型配置决定。

文生模式下粘贴或拖入受支持素材，会切换到对应的图生或全能参考模式。上传中禁用模式、模型和参数修改；不兼容格式及超限文件在上传前拦截。

视频协议的 `function_mode`、`functionMode` 或 `mode` 字段只有在其枚举值能明确匹配时，才由模式控件管理。图生优先采用 `first_last_frames`／`frames`，全能参考使用 `omni_reference`／`references` 等已声明选项；不会向模型发送未声明的枚举值。`frames` 模式要求两张图片，`first_last_frames` 至少要求首帧，其他必填要求仍由模型校验。

首尾帧按上传顺序提交。尾帧槽位在首帧存在后开放；移除首帧时同时清空尾帧并提示，避免尾帧被默默当成首帧提交。

本地验证命令：

```text
npm run test:studio-modes
npm run test:studio-modes-ui
```

浏览器专项测试强制使用 MySQL 3307 和 Redis 6380 的隔离环境，验证模式映射、帧顺序、素材清理、按钮禁用和桌面／平板／手机深浅主题布局，不提交任何生成任务。原有创作与 OpenCrow 流程使用本地演示／模拟服务回归。

## 2026-10-29 再次复查

本轮复现并修复了以下边界情况：

- 自动选模式按可保留的素材数量决定；不支持首尾帧的模型接收两张图片时，优先选择能保留两张的参考模式，避免第二张被单图模式丢弃。
- 上游仅提供 `multi_frame` 时，只开放图片入口。没有图片能力时禁用该模式，不把模型的其他音频／视频字段误当成此协议支持的输入。
- 选择 `frames` 前同时检查图片数量与合计上限；不足两张时，使用协议声明的其他可用映射，或禁用不可实现的模式。
- 修改分辨率后重新计算上游模式和素材容量，避免使用新的单图限制却继续发送必须双帧的参数。
- 资产库按剩余合计名额限制所有素材类型；合计上限用满后，超额素材不能选择，也不会先上传再被丢弃。

新增 5 个边界测试先失败、修复后通过。浏览器 40 条原有流程、9 条模式专项流程与 4 条 OpenCrow 模拟流程全部通过，无页面异常。构建与凭据扫描通过；真实模型与支付调用为 0。
